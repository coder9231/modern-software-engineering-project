# 决策 0001：统计工具首版

状态：已实现；本决策仅确定统计工具的首版实现，不确定整个课程项目的技术栈。

## 问题与选择

团队需要先获得一个能够运行和验证的代码量统计工具。当前工作环境有 Node.js，首版采用 Node.js 20+ 的标准库和命令行入口，避免安装第三方运行依赖。统计核心与文件访问、报告输出分开，后续可以复用核心逻辑添加网页或客户端界面。

## 范围与验收

首版支持文件和递归目录输入、8 种语言、总行/代码/注释/空白分类、按语言汇总、可选文件明细、默认和自定义排除、JSON/CSV 导出。具体规则和边界见 [工具说明](../../tools/code-counter/README.md)。

验收以固定样例和独立预期为依据：示例目录合计 2 个文件、14 行，其中代码 8 行、注释 4 行、空白 2 行。自动测试核对混合注释、字符串、多行结构、编码、路径、排除规则、错误与导出行为。

## 取舍

采用词法分类获得轻量、可复用的统计能力。复杂语言语法仍有已说明的局限，首版不声称与编译器语法分析等价。新语言或复杂语法的支持，应先补充人工可核对的样例和预期，再调整统计规则。

## 课程实践

本次将需求转为明确的统计规则与验收条件，分别组织统计、扫描和输出模块，并用测试与样例保留验证证据。后续需求变更时继续记录范围、估算、实际耗时与设计取舍；本次没有事先记录工期估算，不补写虚构估时。
