# 决策 0003：共享数学核心的四则运算与 24 点

更新日期：2026-10-16。状态：核心、服务、CLI、网页与 OCR 适配器已实现，数学 43 项自动测试通过；已完成生产构建并发布网站第 3 版，本地与线上数学 HTTP 均为 8 项通过。OCR 仅模拟接口验收，浏览器已验收范围与剩余项另见[测试记录](../arithmetic-test-results.md)。

## 背景与目标

课堂图片展示从简单出题程序演进为可定制软件、网站服务的过程。本轮选择四则运算作为自主功能：可配置出题、练习批改、打印、历史、双语界面，以及重用已有模块的 24 点游戏。保留代码量统计和个人展示入口。

实现首先让规则可解释、结果可复现、边界可测试，再分别验证功能与容量。初始“两个运算符”按每题 2 个运算符解释，默认使用加减法；这些是本轮可修改的设计选择，而不是课件未明确给出的事实。

## 表达式解析与精确计算

`website/lib/math/core.mjs` 是唯一数学核心。词法分析仅接受数字、四则运算符及括号；调度场算法把中缀表达式转为逆波兰表达式，栈式求值器处理优先级、一元正负号及括号。不会调用 `eval` 或执行上传内容。

数值以 `BigInt` 分子、分母表示，每次运算约分，避免 `0.1 + 0.2` 的浮点误差。普通答案以精确值比较；带余数除法单独比较整数商与余数。表达式长度、数字长度、记号数和运算符数都有界，防止任意输入导致无界计算。

## 配置、去重与复现

规范化配置集中校验题量、范围、运算符、括号、负数、分数、除法模式与种子。余数模式被限制为非负整数的一次除法；无效组合直接报错。答案范围和操作数范围分别设置。

生成过程形成表达式结构，对加法与乘法同类节点展开并排序，以结构指纹去重；消除交换、结合变形，保留其他不同计算结构。低接受率的整除配置增加有界构造式生成，减少纯随机拒绝的失败概率。题空间不足或达到搜索限制时明确失败，不用重复题补足；搜索达限不等于已经证明题空间不足。

随机种子与规范化配置随题目一起返回。固定种子有助于复现缺陷、核对答案、重复教学练习和公平比较测试。未指定种子时随机生成；配置接口的默认规则不携带固定种子，避免所有用户打开页面后拿到同一套题。

## 重用与接口边界

网页 API 和 `tools/arithmetic/cli.mjs` 直接导入同一核心；CLI 只承担参数和文件输出，服务只承担请求校验与响应。24 点求解器复用精确有理数运算与表达式求值器；校验还要求给定的 4 个整数各使用一次，防止用额外数字或直接填写 24 通过。

| 接口 | 职责 |
| --- | --- |
| `GET /api/math/config` | 默认配置、题量上限、规则与不含密钥的 OCR 状态 |
| `POST /api/math/generate` | 校验配置并生成完整、不重复的练习 |
| `POST /api/math/grade` | 根据算式重新计算答案并批改 |
| `POST /api/math/evaluate` | 返回精确答案及逆波兰表达式 |
| `POST /api/math/24` | 新题、提示与答案校验 |
| `GET /api/math/ocr` | 安全配置状态与图片限制 |
| `POST /api/math/ocr` | 访问码校验、图片转录与待人工复核的题目 |

数学服务无状态，不读服务器文件路径，不写数据库，不持久保存题目或作答。JSON 接口沿用统计服务的真实流式 6 MiB 请求上限、同源与 Content-Type 校验。已知错误返回稳定错误码和可展示说明，意外错误不泄漏内部信息；结果标记为不缓存。

练习准确率、耗时、配置与种子摘要保存在本机浏览器，最多 50 条；存储失败不阻塞练习。换浏览器、清除数据或换设备后没有共享记录。这一选择适合首轮演示，未来若增加班级作业，需要重新设计认证、权限、持久化及个人数据处理。

## AI 边界

AI 仅作为图片转录器，输出候选题目及作答，保留人工校正。数学核心重新求值、批改；AI 输出的评分和“标准答案”不作为权威依据。识别不确定或无法识别时需要明确说明，不能伪造成功结果。

本次 AI 密钥配置流程中断，尚未取得真实密钥，本轮不启用真实识别服务。适配接口与人工校正路径独立于出题功能，未配置时明确返回 503。未来启用时，只有服务器同时具备 `OPENAI_API_KEY` 和 `OCR_ACCESS_TOKEN` 才报告配置完成；密钥不下发前端，公开站点的识别请求还需访问码。访问码仅保存在输入页内存中，不存入浏览器历史。

服务仅向固定的 OpenAI Responses 端点发请求，不接受图片 URL；图片采用 Base64，限制为 4 MiB 的 PNG/JPEG/WebP 并校验文件签名。输入 JSON 受 6 MiB 流式上限约束，识别请求设 45 秒超时，响应上限 128 KiB、最多 100 行。结构化输出仅允许算式、学生答案和不确定标记，拒绝评分字段；转录结果不能直接作为正确答案。图片不写入站点持久存储，仅在用户点击识别后发送给外部服务；`store:false` 不等同于外部服务完全不保留任何数据。

默认模型为 `gpt-5.6-terra`，可用服务端 `OPENAI_OCR_MODEL` 覆盖；实际模型权限、额度及识别准确率需配置后实测。适配器依据[图片输入文档](https://developers.openai.com/api/docs/guides/images-vision)、[结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)和[模型页](https://developers.openai.com/api/docs/models/gpt-5.6-terra)编写。当前测试全部使用注入的模拟响应，不能代替真实图片识别验收。变量名示例见 `website/.env.example`，真实值应通过服务端运行环境配置，禁止提交到仓库。

## 验证与限制

核心测试覆盖优先级、分数精度、规则边界、结构去重、确定性、1 万道题和 24 点。服务和 CLI 测试覆盖严格字段校验、伪造客户端标准答案、流式上限、跨站请求、参数与安全输出。OCR 测试通过注入模拟响应校验图片、配置、访问码及上游异常边界，不产生识别服务调用。

数学 43 项自动测试已通过，本地与线上第 3 版均通过数学 HTTP 8 项、代码统计 HTTP 6 项；官方生产构建完成，部署状态为 `succeeded`。本地开发服务完成 5 并发、100 请求的短时测量。具体版本、环境、延迟、吞吐量和未验收范围见测试记录；新版本 GitHub CI 仍需核实。

单次生成 10000 道题不等于支持 10000 个并发用户。当前未实现多租户、班级、账号、服务端学习记录或生产容量保障；不把本机 Node 用时写成线上性能承诺。后续根据实际运行环境、请求模型、峰值时段、延迟和错误率目标制定容量方案并记录真实结果。
