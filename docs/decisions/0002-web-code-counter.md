# 决策 0002：将统计工具整合进项目网站

日期：2026-10-15。

状态：网站首版前后端已实现；构建、线上发布与访问验证分别记录，不将预留域名视为已部署证据。

## 问题与选择

团队需要在最终网站中直接使用代码量统计工具，并提供线上演示。网站同时作为后续自主功能、课程实践记录及个人主页的展示入口。

采用 React/Vinext 的 Sites 项目，源码位于 `website/`，使用 App Router 风格的页面及 API 路由。运行网站需要 Node.js 22.13.0 或以上。前端负责文件选择、分批、结果聚合与展示；后端负责输入校验、编码解码、权威过滤、词法统计和报告导出。

`website/` 是独立的 Sites Git 工作区，具有自己的发布生命周期。上层课程项目与内层网站的提交及发布需要分别核对，不能用上层仓库的一次提交推断网站已经发布。

## 共享核心与接口边界

`website/lib/code-counter/analyzer.mjs` 与 `report.mjs` 是统计和格式化的唯一维护位置。命令行目录中的同名文件 re-export 共享实现，CLI 保留文件系统扫描职责，网站服务通过内存中的上传内容调用同一分析器。修复统计规则时，两种入口使用相同实现，并通过测试比较结果。

网站后端为无状态服务：不接受客户端指定的服务器文件路径，不执行源码，不把源码或报告写入数据库、磁盘或对象存储。浏览器提交的是相对文件名及 Base64 内容；统计和导出在请求期间完成。

接口为：

| 接口 | 职责 |
| --- | --- |
| `GET /api/health` | 检查服务响应 |
| `GET /api/code-count/config` | 获取语言、默认排除、限制及规则 |
| `GET /api/code-count/demo` | 实际分析固定样例，返回可核对结果 |
| `POST /api/code-count` | 校验一批上传条目并统计 |
| `POST /api/code-count/export` | 校验聚合报告，返回 JSON 或 CSV 附件 |

## 取舍

采用每批最多 100 个文件、4 MiB 原始内容、单文件最多 4 MiB 的限制。浏览器按批次顺序提交大型项目；服务先限制请求流的实际字节数，再解析 JSON，以控制 Base64 和元数据带来的额外开销。超过单文件限制的条目在浏览器记录为跳过。CLI 仍保持独立的文件大小配置，不能将网站上限误认为 CLI 的默认值。

报告按物理行分类；词法分析的能力及局限沿用决策 0001。排除模式、编码、扩展名与二进制校验由后端处理。导出接口重新核对文件明细和语言汇总，CSV 文件名按文本输出，避免被电子表格解释为公式。

站点演示地址为 [软件工程实践站](https://se-practice-coder9231.a0910663736.chatgpt.site)。2026-10-15 根据项目要求将访问策略改为公开，无需登录 ChatGPT 账号。GitHub 仓库写入权限与站点访问策略分别管理，公开源码不会自动授予仓库写入权限。

当前未实现用户数据持久化，也未验证一万用户同时访问的能力。课程图片中的规模要求应作为后续容量规划、部署设计及压测的输入，不能由本次功能测试推断已经满足。

## 验证与后续

自动测试比较网站与 CLI 在 8 种语言及排除模式上的一致性，并覆盖 UTF-8、UTF-16 BOM、GB18030、伪装图片、路径校验、严格 Base64、流式请求上限、精确 4 MiB 输入、无源码执行和报告校验。具体命令见 [网站说明](../web-code-counter.md)。

后续根据课堂要求确定自主功能，补充真实的个人介绍、团队信息及展示材料，并记录需求验收、估时与实际耗时、反馈和复盘。本轮没有事先留存完整工期估算，不补写虚构估时。
