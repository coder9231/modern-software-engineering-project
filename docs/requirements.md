# 需求草案

本文件用于逐步澄清范围。下列验收与统计规则是讨论起点，尚未成为最终约定。

## 已确认的方向

- 结合《现代软件工程》课程，长期迭代完成一个网站或客户端项目。
- 首先完成代码量统计工具，再完成自主设计功能，最后展示个人主页与成果。
- 团队共同开发，并保留需求、设计、验证和复盘记录。

## 待确认的问题

| 问题 | 当前状态 |
| --- | --- |
| 课程任务说明、评分标准和提交时间 | 待提供 |
| 网站或客户端，以及技术栈 | 待团队讨论 |
| 统计工具支持的语言与输入方式 | 待确定，建议首版聚焦一两种语言 |
| 注释与代码的分类规则 | 待确定并准备样例 |
| 自主功能的使用者、场景与主题 | 待确定 |
| 个人主页的内容、展示方式及团队成果归属 | 待确定 |
| 成员职责、迭代安排和评审分工 | 待填写团队文档 |

## 统计工具首版范围建议

输入代码文件或项目目录，按文件及语言展示总行数、代码行、注释行和空白行，并提供汇总。目录模式可排除依赖与构建产物；具体默认排除项应在实现前确认并向使用者说明。

## 首版验收条件草案

| 场景 | 建议的验收结果 |
| --- | --- |
| 支持语言的示例文件 | 各项统计与已人工确认的预期一致 |
| 含多个受支持文件的目录 | 文件明细与汇总一致，按约定规则排除文件 |
| 空文件 | 各项行数为零 |
| 多行注释、代码与注释混合、字符串中的注释符号 | 按最终确认的规则分类，并用固定样例验证 |
| 不支持的文件或读取失败 | 明确说明跳过或失败原因，避免生成误导性统计 |
| 同一输入重复分析 | 在相同配置下得到一致结果 |

## 统计规则讨论清单

- 采用物理行还是逻辑语句计数？建议首版采用物理行。
- 空白行如何定义？文件末尾换行是否额外算一行？
- 一行同时含代码和注释时如何分类？各类是否互斥？
- 多行注释内的空白行归入哪一类？
- 字符串里的注释符号、转义字符和语言特有语法如何处理？
- 哪些扩展名、编码和换行格式属于首版支持范围？
- 是否递归统计子目录，如何处理隐藏目录、符号链接和排除配置？

规则确认后，记录决定和理由，补充可手动核对的输入与预期输出，再据此实现与验收。代码量不作为个人贡献或代码质量的单一评价依据。
